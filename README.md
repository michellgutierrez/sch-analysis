# Flowline LBM (web version)

Static page that compares two Primavera P6 schedules (XER) with flow bands by level and a
milestone-movement comparison. All processing runs in the browser: the XER files are not
uploaded to any server. The interface and the report are available in English and Spanish.

## Contents

- `public/index.html` — the whole application (HTML, CSS and JavaScript in one file).
- `firebase.json` — Firebase Hosting configuration.
- `vercel.json` — Vercel configuration.

## Try it locally

Open `public/index.html` with a double click, or serve the folder:

    python -m http.server 8000 --directory public

## Deploy to Firebase Hosting

    npm install -g firebase-tools
    firebase login
    firebase deploy --only hosting --project YOUR_PROJECT_ID

## Deploy to Vercel

    npm install -g vercel
    vercel --prod

If Vercel asks for a framework, choose "Other" and leave the build command empty.

## Use

1. Drop the reference XER and the XER to compare.
2. Pick the language, adjust the schedule names and, optionally, the "Today" date.
3. Press "Generate report". "Download CSV" exports dates by task and level.

## Grouping modes

- **Proposed bands (Activity ID rules)**: seven bands defined by Activity ID patterns, tuned to the
  Domus II coding (C-<level>-<zone>-<discipline>-<nnn>).
- **Schedule WBS**: the bands are the scheduler's own WBS groups at the level you choose (level 2
  areas such as Building Structure or Interior MEPs & Finishes, level 3, level 4, or the lowest,
  per-floor groups). Groups present on fewer than 3 floors are left out; beyond 8 bands the
  smallest fold into "Other WBS groups". The floor level still comes from the Activity ID, or from
  the WBS name ("20th Lvl") when the ID has none.
- **Custom JSON**: whatever rules are in the JSON box. Editing the box switches to this mode.
  "Load JSON…" opens a saved rules file and "Download JSON" saves the current one, so the rules
  generated by the other two modes can be used as a starting point.

## Adapting it to another project

Open "Grouping rules (editable JSON)" on the page:

- `level_regex_code`: regular expression on the Activity ID; group 1 is the level number.
- `tasks`: summary tasks in construction order. `code` and `name` are regular expressions on the
  Activity ID and the activity name; the first rule that matches wins. `label_en` / `desc_en`
  hold the English text. A rule can also use `wbs` (regular expression on the full WBS path) or
  `wbs_depth` + `wbs_group` (list of WBS names at that depth, level text removed). Eight colours
  are available, one per band.
- `milestones`: milestones drawn on the flow charts, by Activity ID, with the levels they cover.
- `milestone_compare`: milestones in the movement comparison. Use `code` when the Activity ID is
  the same in both schedules, or `code_a` / `code_b` when it differs.
- `zones`: horizontal dividers between groups of levels.

To make new rules the default, edit `DEFAULT_CONFIG` inside `public/index.html`.

# Flowline LBM (versión web)

Página estática que compara dos cronogramas Primavera P6 (XER) con bandas de flujo por nivel y
un comparativo del movimiento de hitos. Todo corre en el navegador: los XER no se suben a ningún
servidor. La interfaz y el reporte están en inglés y español; el idioma se elige en la página.

La agrupación se elige en la página: bandas propuestas (reglas por Activity ID), WBS del
cronograma (nivel 2, 3, 4 o el más bajo) o JSON personalizado, que se puede cargar y descargar.
Los pasos para probar, desplegar y adaptar son los mismos de arriba.
